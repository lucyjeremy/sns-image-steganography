# 메신저·SNS 업로드 환경에서의 이미지 스테가노그래피 보존성 및 탐지 분석

정보보안학회 SISS 16주 개인 연구 (2026)

이미지에 숨긴 정보가 메신저·SNS의 압축을 견디는지, 압축된 이미지에서 은닉 흔적을 찾을 수 있는지, AI 생성 이미지의 워터마크가 SNS를 견디는지를 실제 6개 플랫폼(카카오톡·라인·텔레그램·X·페이스북·인스타그램)에서 측정함.

## 연구 질문

| 질문 | 관점 |
|---|---|
| 숨긴 정보가 압축을 견디는가 (보존) | 비밀 통신·기밀 유출 |
| 압축된 이미지에서 은닉 흔적을 찾을 수 있는가 (탐지) | 수사·디지털 포렌식 |
| AI 생성 이미지의 워터마크는 SNS를 견디는가 (판별) | 딥페이크 대응 |

## 주요 결과

| 축 | 결과 |
|---|---|
| 보존 | 축소가 일어나지 않는 512px에서 DCT 은닉은 6개 플랫폼 모두 98~100% 복구, LSB·워터마크는 49~53%(정보 소실). 인스타그램이 1024px를 960px로 6%만 줄여도 DCT 복구율은 58%로 떨어짐 |
| 탐지 | 실제 사진(BOSSBase, 256px, 용량의 40% 삽입)에서 Chi-square 65.8%, SRM 필터 + CNN은 LSB 89.5%·DCT 99.2%. 삽입량·삽입 위치·삽입 강도를 모두 바꿔도 압축을 견디면서 탐지를 피하는 조합은 없었음 |
| 판별 | 딥러닝 워터마크(rivaGan)는 JPEG 압축은 견디지만 리사이즈 후 51%로 소실. 상용 SynthID는 압축·편집 공격·실제 SNS 왕복을 모두 통과 |
| 방법론 | 합성 이미지로 실험하면 CNN 탐지 정확도가 100%(실제 사진 41%)로 부풀려지고, Chi-square 판정 방향과 구성 요소 기여도 판단까지 뒤집힘 |

## 실험 설계와 검증

- **실제 플랫폼 왕복**: 은닉 이미지를 PNG로 올려 받은 뒤 추출하고, 원본과의 일치율로 보존성을 측정함. 6개 플랫폼 모두 JPEG으로 변환해 돌려줌
- **표본 확대**: 업로드·다운로드가 수작업이라 처음에는 조건당 2장뿐이었음. 128px 이미지 16장을 4×4로 합쳐 512px 한 장으로 보내고 받은 뒤 다시 자르는 방식으로 640장까지 늘림. 128은 8의 배수라 JPEG 8×8 블록 경계와 맞아 따로 압축한 것과 결과 차이가 0임을 확인함
- **전처리 점검**: 수신 이미지를 리사이즈한 뒤 분석하면 은닉 흔적도 사라짐(리사이즈 없이 98.1~100%, 256px 리사이즈 후 50.0%). 분석은 리사이즈 없이 진행함
- **신뢰도**: 핵심 수치는 시드 3회 반복과 Welch t-검정으로 확인함. 은닉 없는 이미지에 무작위 라벨을 붙여 학습시키면 52.2%로, 허위 패턴은 학습하지 않음
- **교차 데이터셋**: BOSSBase로 학습한 모델을 BOWS2로 테스트했을 때 AUC 0.94 유지, P_E는 51% 나빠짐

## 노트북 구성

`steganography_analysis.ipynb` 한 파일에 주차별로 정리함. 셀 대부분은 다른 셀 없이 단독으로 실행되도록 작성함.

| 주차 | 내용 |
|---|---|
| 2~5주차 | LSB 은닉·추출 도구, 정확도 검증, Chi-square 탐지와 ROC 임계값 |
| 6~8주차 | LSB 플랫폼 실험, DCT 은닉 구현, Q 튜닝·파라미터 최적화·강건화(중복 삽입, ECC) |
| 9~10주차 | CNN 탐지, Ablation, SRM 필터 CNN, 압축 강도별 탐지율 |
| 11~12주차 | 워터마킹(DWT-DCT) 압축 저항성, SynthID 검증 |
| 13~14주차 | BOSSBase로 데이터셋 통일, BOWS2 교차 검증, 실제 SNS 왕복 검증, 보존성–탐지 트레이드오프 |
| 이후 | 시드 반복·Sanity check·P_E 등 신뢰도 검증, rivaGan·HILL·STC 등 한계 보완 실험 |
